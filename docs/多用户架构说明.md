# 🧑‍🤝‍🧑 多用户架构说明（v1.2）

## 概述

跑步打卡网站从"单机版"升级为"多用户版"：
- **公开注册**：任何人拿到网址都能注册自己的账号
- **数据隔离**：每个账号的数据（打卡、体重、照片、设置）完全独立，互相看不到
- **云端保存**：数据存在 Cloudflare 云端，换手机/清缓存不丢
- **登录态**：登录一次保持 30 天（HttpOnly Cookie），微信里不用每天输密码

## 技术架构

```
浏览器（微信内 H5）
   │  HTTPS + HttpOnly Cookie 会话
   ▼
Cloudflare Pages（静态页面）
   │  /api/* 路由到 Pages Functions
   ▼
Pages Functions（后端 API，Worker 运行时）
   │  D1 绑定：env.DB
   ▼
Cloudflare D1（SQLite 数据库）
```

## 数据库表结构

| 表 | 字段 | 说明 |
|---|---|---|
| users | id, username(唯一), password_hash, salt, created_at | 用户；密码 PBKDF2-SHA256 10万次 + 随机盐 |
| sessions | token(主键), user_id, expires_at | 登录会话，30 天有效 |
| records | user_id, date, data(JSON), updated_at | 每日记录：跑步/体重/请假/照片ID |
| photos | user_id, date, mime, data(BLOB), updated_at | 每日照片（压缩后约 150KB，上限 2MB） |
| settings | user_id, data(JSON), updated_at | 用户设置：每周目标、提醒时间等 |

所有查询都带 `WHERE user_id = ?`，数据库层面强制隔离。

## API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/register | 注册 {username, password} → 自动登录 |
| POST | /api/login | 登录 {username, password} |
| POST | /api/logout | 退出登录 |
| GET | /api/me | 当前登录用户 |
| GET | /api/data | 拉取全部记录 + 设置 |
| PUT | /api/data | 整体覆盖（导入备份用） |
| PUT | /api/records?date=YYYY-MM-DD | 单日记录 upsert |
| DELETE | /api/records?date=YYYY-MM-DD | 删除单日记录 |
| GET/PUT | /api/settings | 读取/保存设置 |
| GET/PUT/DELETE | /api/photo?date=YYYY-MM-DD | 照片读取/上传/删除 |

鉴权：所有数据接口要求有效会话 Cookie，否则返回 401。

## 安全设计

- 密码：PBKDF2-SHA256，10 万次迭代 + 16 字节随机盐，不存明文
- 会话：64 位十六进制随机 token，HttpOnly + Secure + SameSite=Lax Cookie，30 天过期
- 隔离：所有 SQL 查询强制按 user_id 过滤
- 防注入：全部使用参数化查询
- 照片：登录后清空本地照片缓存，避免同设备多账号串图
- 限制：单张照片 ≤ 2MB；用户名 2~20 位（中文/字母/数字/下划线）；密码 6~64 位

> ⚠️ 已知限制：忘记密码暂不支持自助找回（无邮件服务）。建议注册时把密码记在密码管理器里。

- 数据库名：`run_checkin_db`
- GitHub Actions 自动部署同样自动包含 Functions
